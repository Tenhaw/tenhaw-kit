# Implementation decisions

15 November 2026. These decisions incorporate the PRD review and James's subsequent instructions.

1. **Agent interfaces first.** The purpose is useful open-source infrastructure for people building internal product, portfolio, delivery and transformation products. The consultancy relationship is a medium-term by-product. Packages, JSON Schemas, CLI, MCP and skills are primary. Keep docs a compact reference and tenhaw.com to one entry point.
2. **Keep scoring.** James approved readiness scoring. It is a repeatable self-assessment framework, distinct from the advisory audit. Show weights, evidence and coverage. Empty scores are null; maturity bands need 80% coverage. Coverage is not statistical confidence.
3. **Cash and capacity.** Preserve the existing website's distinction between retained capacity and actual cash savings. An explicit cashRealisation fraction drives cash flow. Retained capacity is reported separately and is not cash.
4. **Five DORA metrics.** Current DORA guidance adds deployment rework rate. Only real production evidence is counted; tags/merges are labelled proxies and excluded. Metrics describe one service at a time. No fabricated composite score or universal performance bands.
5. **Data boundary.** Local CLI/stdio may collect using environment credentials and cache normalised events. Remote MCP accepts aggregate delivery reports only, never raw repository events or credentials. Input and output schemas are shared; body size is capped at 256 KB. Request bodies are not logged or persisted.
6. **Safe starter defaults.** Five Next.js starters use browser-local imports/storage and synthetic demos, not unauthenticated shared databases. Deploying shared Postgres/SQLite persistence or hosted Cron collectors requires an explicit authenticated architecture extension. Vercel Standard Protection excludes production domains and is insufficient by itself.
7. **No installation telemetry.** No package, CLI or MCP usage pings. The compact reference site ships without analytics. Optional website analytics must be disclosed separately; do not publish a blanket no-data-storage promise for hosting metadata or analytics.
8. **Licences.** Optional marketing is separate from CC BY framework credits. Reports reproducing framework content retain its credit even when marketing is suppressed. Canonical metadata, legal credits, service endpoints and technical source citations are exempt from marketing UTM lint.
9. **Repository owner.** Use Tenhaw, matching the verified GitHub account and website repository. Tenhaw Media is a retired offshoot. Name availability is checked with exact status codes; errors are unverified. Pending PyPI publishers do not reserve names.
10. **MCP generation.** Official build-day docs identify SDK v2 (`@modelcontextprotocol/server` 2.4.0) and `mcp-handler` v2 as current. Use these instead of legacy `@modelcontextprotocol/sdk` v1. The SDK serves current 2026-07-28 and 2025-era clients. Portable OpenAI plugin manifests use Agent Plugins schema 1.0.0; no lifecycle hooks.
11. **Local verification before release.** Build libraries, CLI/MCP and templates; use packed tarballs to test clean installs before public release. Only then publish, verify exact registry versions, sync satellites and test public install paths. Do not require unpublished packages during pre-release verification. Preview verification precedes merge; production checks follow deployment.
12. **Release authentication and triggers.** Trusted npm/PyPI publishers use a protected GitHub release environment. Satellite sync uses a narrowly scoped GitHub App token and explicit reusable-workflow invocation, not implicit tag-event chaining with GITHUB_TOKEN. Registry publication is an explicit job/dispatch after package and endpoint verification.
13. **Lean docs implementation.** A small static Next.js reference replaces Fumadocs/Nextra to keep dependencies, UI and maintenance small. JSON references, schemas, llms.txt, OpenAPI and runnable examples carry most detail. Browser QA is reported separately from build/type/unit checks.
14. **Python models.** Validate directly against packaged copies of the shared JSON Schemas rather than maintaining a second Pydantic interpretation. Sync checks require byte-identical schemas/content; both runtimes execute the same golden vectors.
15. **Versioned assumptions.** Project cost ranges are editable planning assumptions, not quotes. No model prices are invented or fetched implicitly. EU AI Act risk summaries are indicative and transparency duties can overlap risk categories.
