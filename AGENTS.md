# Working on Tenhaw Kit

Build useful primitives for agents creating internal product, portfolio, delivery and transformation tools. Packages, schemas, CLI and MCP are the primary interfaces. Keep the website a compact reference.

- Run Node 22.14+, pnpm install, pnpm check, uv sync, uv run pytest, uv run ruff check and uv run mypy.
- Run pnpm build:apps and pnpm build:templates for application changes.
- Keep spec/schemas, versioned content and shared golden vectors authoritative. TypeScript and Python must emit identical canonical JSON.
- Readiness scoring is a self-assessment framework, distinct from Tenhaw's workflow-based advisory audit. Show coverage and evidence; suppress maturity bands below 80% coverage.
- Separate recoverable capacity from actual cash savings. DORA metrics need production evidence and incident linkage; missing data is null.
- Collect credentials locally from environment variables only. Remote tools accept bounded aggregate metrics, never raw repository events or credentials.
- Scaffolding never overwrites files or agent instructions. Default templates are browser-local synthetic demos; shared data requires authentication and an explicit architecture extension.
- No telemetry in packages, CLI or MCP. Website analytics, when explicitly enabled, have a separate privacy disclosure.
- Marketing attribution is removable. Preserve applicable framework licence notices when reproducing CC BY content.
- British English, no client names or invented evidence, and no em dashes in public copy.
- Use branches and pull requests. Never infer that a registry name is free from an authentication or network error. Never claim publication without verifying the exact version.
- Existing tenhaw.com styles and layouts are out of scope. New entry content reuses existing components.
- Before writing Next.js code, read the relevant node_modules/next/dist/docs guides.
